    Klong for q users¶

    This page is for people who know q and want to read or write Klong. It maps the idioms, lists the differences that cause mistakes, and describes how a KlongPy program and a q process talk to each other over the kdb+ IPC protocol.

    The q examples on this page were checked with PeachQ 0.92, a third-party open-source implementation of q. PeachQ is not kdb+: where the page says what q prints, it means what PeachQ 0.92 printed, and the page makes no claim about kdb+ beyond that. Conditions: every q result shown is from PeachQ 0.92. The Klong examples run at strict level 2, except the sessions that need a q process.

    kdb+ is a trademark of KX. KlongPy's IPC is an independent implementation, written from public documentation and Apache-licensed client code. It speaks the kdb+ IPC protocol and interoperates with q processes; it is not a KX product and uses no KX code.

    If you have not used Klong at all, read the tutorial first or alongside this page. The operator reference is the lookup table.

    What carries over¶

    Klong and q are both array languages in the APL line, and the shape of a program is the same.

    • Evaluation is right to left and there is no operator precedence. 2*3+4 is 14 in both.
    • A verb is a monad or a dyad by position. -x negates and a-b subtracts.
    • Adverbs modify verbs: ' each, / over, \ scan. +/x sums, +\x is the running sum.
    • A function takes its arguments as x, y and z, and its rank is the highest of them that its body uses.
    • Lists are the basic data type, and most verbs apply to every element of a list.
    • Strings are lists of characters, symbols are atoms, and a dictionary maps keys to values.
    q)2*3+4
14
q){x+z}[1;2;3]
4

    ?> 2*3+4
14
?> {x+z}(1;2;3)
4

    Klong is smaller than q. It has integers, floats (doubles), characters, strings, symbols, lists, dictionaries and functions. It has no boolean, no temporal types, no typed nulls, no q-sql and no namespaces. A file is a module, a dictionary of the names it exports, and a.b reads the entry b of a.

    What is different¶

    A leading minus is a verb¶

    In q, -1+2 is 1: the -1 is read as a number. In Klong a leading - is the negate monad and applies to everything to its right, so -1+2 is -(1+2), which is -3. A negative number is written inside a list ([-1 2]) or in parentheses. Lint warns about the trap as W010.

    q)-1+2
1
q)(-1)+2
1

    ?> -1+2
-3
?> (-1)+2
1
?> [-1 2]
[-1 2]

    The same rule makes a slice from the end (-2)#y or (0-2)#y, not -2#y.

    Calls and indexing¶

    Square brackets build lists in Klong. They never index or call. A call is f(a;b), indexing is a@i, and applying a function with @ works too: f@x. A one-argument call needs no space and a space before the parenthesis is a lint warning (W014).

    q){x+y}[1;2]
3
q)3 1 2@1
1

    ?> f(a;b)::{a+b}
:dyad
?> f(1;2)
3
?> [3 1 2]@1
1
?> f(1;)@10
11

    A call with fewer arguments than the function takes is a projection, as in q. Klong writes the missing argument as an empty slot or leaves it off: f(1;) and f(1) both give a projection. A call with too many arguments drops the extras at strict levels 0 and 1 and is an arity error at level 2.

    Assignment is :: everywhere. In q, :: inside a function assigns a global; in Klong it is plain assignment, and a name that is not a parameter, not declared as a local ({[t];...}) and not already global becomes a local of that call at level 0 and is an error at strict levels 1 and 2. A global is created by assigning at the top level. Outside functions, d:::{...} is the assignment d:: followed by the dictionary literal :{...}. See strict mode.

    ?> total::0
0
?> bump(n)::{total::total+n}
:monad
?> bump(5)
5
?> total
5
?> scaled(n)::{[t];t::n*2;t+1}
:monad
?> scaled(5)
11

    Klong has named parameters, f(a;b;c;d)::{...}, with no limit on their number. The q names x y z also work in a bare {...}: {x+y} is a dyad, and it is the short form to give an adverb. Destructuring takes the place of q's a:x 0;b:x 1.

    No booleans¶

    Comparisons return the integers 0 and 1. There is no 1b, and no boolean vector type; the verbs that take a mask (&, ~) take 0 and 1. The conditional is :[c;a;b], where q has $[c;a;b]. An else-if chain is :[c1;a:|c2;b;d].

    q)3>2
1b
q)$[1<2;"yes";"no"]
"yes"

    ?> 3>2
1
?> :[1<2;"yes";"no"]
"yes"
?> sign(n)::{:[n<0;"neg":|n=0;"zero";"pos"]}
:monad
?> sign'[-5 0 7]
["neg" "zero" "pos"]

    A condition is false for 0, for an empty list and for an empty string; everything else is true.

    Nulls: :undefined¶

    q has a typed null for each type (0N, 0n) and infinities (0w). Klong has one undefined value, written :undefined. It is what a division by zero gives, what a missing dictionary key gives, and what a failed conversion gives. Test for it with the :_ monad.

    q)1%0
0w
q)0%0
0n
q)(`a`b!1 2)`zz
0N

    ?> 1%0
:undefined
?> :_(1%0)
1
?> d:::{[:a 1] [:b 2]}
:{[:a 1] [:b 2]}
?> d@:zz
:undefined
?> :_d@:zz
1
?> 1:$"x"
:undefined

    A list that holds :undefined can be printed and indexed, but arithmetic on it is an error. Nulls are not translated over IPC: see the type table.

    Find, group and the dyad ?¶

    q's x?y returns the index of the first match, or the count of x when there is none. Klong's x?y returns the list of all matching indices, empty when there is none. Use * on the result for the first match.

    q)3 1 3 2 1?3
0
q)3 1 2?5
3

    ?> z::[3 1 3 2 1]
[3 1 3 2 1]
?> z?3
[0 2]
?> z?7
[]
?> *z?3
0

    =z is group, and it returns only the lists of indices, ordered by the first appearance of each value: =[3 1 3 2 1] is [[0 2] [1 4] [3]]. q's group returns a dictionary keyed by the values. ?z is q's distinct, in order of first appearance, not sorted. For a random number use .rn().

    Scan with a seed¶

    A scan with a seed keeps the seed in Klong. q's does not.

    q)10 +\ 1 2 3
11 13 16

    ?> 10+\[1 2 3]
[10 11 13 16]

    Strings, characters and symbols¶

    A Klong string is a list of characters, like a q string, but a one-character string is still a string: "a" is a string of length 1 and the character is written 0ca. In q "a" is a character atom, which matters over IPC (see below). A symbol is written :abc where q writes `abc, and a list of symbols is [:a :b :c]. A symbol held as data is never looked up as a variable.

    ?> #"a"
1
?> [:a :b :c]
[:a :b :c]
?> foo::5
5
?> {x}'[:foo :bar]
[:foo :bar]

    A list literal holds what is written in it. To evaluate expressions inside a list, start it with a semicolon: [;1+1;2+2] is q's (1+1;2+2).

    ?> [;1+1;2+2]
[2 4]

    Dictionaries¶

    A dictionary literal lists [key value] pairs. Lookup is d@k or d?k, and a missing key gives :undefined. d@[k1 k2] looks up several keys. Joining a pair or another dictionary with , adds entries, and it changes the dictionary in place (q's , returns a new one). A dictionary literal whose keys and values are expressions is :{;k;v;...}. See Language Additions.

    q)d:`a`b!1 2
q)d,`c`d!3 4
a| 1
b| 2
c| 3
d| 4

    ?> d:::{[:a 1] [:b 2]}
:{[:a 1] [:b 2]}
?> e::d
:{[:a 1] [:b 2]}
?> d,:{[:c 3] [:d 4]}
:{[:a 1] [:b 2] [:c 3] [:d 4]}
?> e
:{[:a 1] [:b 2] [:c 3] [:d 4]}
?> d@[:a :zz]
[1 :undefined]
?> *'d
[:a :b :c :d]
?> {x@1}'d
[1 2 3 4]
?> :{;:x;1+1;:y;2*3}
:{[:x 2] [:y 6]}

    Division¶

    % is float division in both languages. x div y is x:%y and x mod y is x!y, with one difference for negative numbers: Klong truncates toward zero where q floors. (-7):%2 is -3 in Klong and -4 in q, and (-7)!2 is -1 in Klong and 1 in q.

    Tables and queries¶

    Both desktop commands provide column tables and run SQL strings through DuckDB. Use .index(t;["col"]) to set a key and .insert to upsert. Pass named tables to .db for live queries, or give .db a path to open a persistent DuckDB file. Use SQL GROUP BY for q-sql by, and translate splayed or partitioned files to a format DuckDB can read. Columnar tables and SQL

    q)t:([] sym:`a`b`a`b`a; px:1 2 3 4 5)
q)exec sum px by sym from t
a| 9
b| 6
q)exec px from t where px>2
3 4 5
q)exec sum px from t
15
q)cols t
`sym`px

    ?> .py("klongpy.db")
1
?> t::.table([["sym" ["a" "b" "a" "b" "a"]] ["px" [1 2 3 4 5]]])
sym px
  a  1
  b  2
  a  3
  b  4
  a  5
?> .schema(t)
["sym" "px"]
?> t?"px"
[1 2 3 4 5]
?> db::.db(:{;"t";t})
:db
?> db("select sym, sum(px) as s from t group by sym order by sym")
[["a" 9.0] ["b" 6.0]]
?> db("select px from t where px>2")
[3 4 5]
?> db("select sum(px) from t")
15.0

    A query returns Klong values. One column can give a list, several columns can give rows, and one cell gives a scalar. t,"qty",,[10 20 30 40 50] adds a column. This example uses the legacy Python adapter for table display. The built-in .db preserves integer sums exactly.

    Timers¶

    q's .z.ts runs once per \t interval. Klong has .timer(name;seconds;callback): a timer is a value, there may be many, and the callback's result decides whether it runs again (1 to continue, 0 to stop). .timerc(t) cancels one. The interval may be fractional. See Timers.

    n:0
.z.ts:{n+::1;show n;if[n>=3;system"t 0"]}
system"t 200"

    That q script prints 1, 2 and 3, one per line, and then stops the timer. The Klong version prints the same:

    n::0
cb::{n::n+1;.p(n);:[n<3;1;0]}
th::.timer("t";0.2;cb)

    Run it with kgpy -l file.kg, which stays in the REPL while the timer fires. kgpy file.kg runs the file and exits without waiting for a timer, so it prints nothing for this program.

    Talking to q: IPC¶

    KlongPy's .srv, .cli, .clid, .clic, .clit and .async speak the kdb+ IPC protocol. A Klong program can connect to a q process, and a q process can connect to a Klong server. The full description, including how functions cross the wire, is in IPC Capabilities. This section is what a q user needs.

    Limits: no TLS, so a user name and password travel in clear text, and a peer that can reach the port can run Klong code in your interpreter, including .py and .sys. The other limits (message size, compression) are in IPC Capabilities.

    The examples use PeachQ 0.92. Both desktop commands have live PeachQ coverage. Set KLONG_TEST_PEACHQ to its executable for the tests in tests/test_ipc_peachq.py, tests/test_native_ipc.py and tests/v2.

    Addresses¶

    q Klong Meaning
    hopen `:localhost:8888 .cli("localhost:8888") or .cli(8888) connect to a port, on localhost for the bare integer
    hopen `:host:8888:user:pw .cli("host:8888:user:pw") with a user name and password, in clear text
    q -p 8888 .srv(8888) or kgpy -s 8888 listen on a port
    .srv(0) stop listening and drop the clients
    hclose h .clic(h) close a connection

    A Klong program calls a q process¶

    .cli returns a function. Call it with a string to evaluate q source in the q process, or with a symbol and arguments to call a function that is defined there by name. A string is source text in the language of the process that receives it. The result comes back as a Klong value.

    Start a q process that listens on port 8888, for example q -p 8888, and then, in a Klong session:

    ?> h::.cli("localhost:8888")
remote[localhost:8888]:fn
?> h("1+1")
2
?> h("til 5")
[0 1 2 3 4]
?> h("`a`b!1 2")
:{[:a 1] [:b 2]}
?> h("mean:{(sum x)%count x}")
:undefined
?> h(:mean,,[1 2 3 4])
2.5
?> h("mean 1 2 3 4")
2.5

    h(:mean,,[1 2 3 4]) is q's h(mean;1 2 3 4): the callee as a symbol, then its arguments. The,,wraps the list so that it is one argument. With two arguments writeh(:add,3,4). Assigning in q returns the generic null, which arrives as:undefined`.

    An error in q comes back as a Klong error of kind remote whose message is the text of the q signal. The connection stays open.

    ?> h("nosuch")
error: nosuch
?> h("1+`a")
error: type
?> h("1 2 3 + 4 5")
error: length
?> h("1+1")
2

    A table from q stays a table on both desktop hosts. The example loads klongpy.db for pandas-backed display. .clid gives the remote context as a dictionary for reading and writing q variables.

    ?> .py("klongpy.db")
1
?> T::h("([] a:1 2 3; b:1.5 2.5 3.5)")
a   b
1 1.5
2 2.5
3 3.5
?> T?"b"
[1.5 2.5 3.5]
?> .schema(T)
["a" "b"]
?> d::.clid(h)
remote[localhost:8888]:dict
?> d,[:foo 2]
remote[localhost:8888]:dict
?> d?:foo
2
?> h("foo")
2
?> .clic(h)
1

    A q process calls a Klong server¶

    Start the server with kgpy -s 8888, or call .srv(8888) in a program. A q client sends a string, which is Klong source, or a call by symbol. These were run against a KlongPy server that had avg::{(+/x)%#x}, add::{x+y}, hello::{"hello, ",x}, data::[3 1 2] and total::100 defined:

    q)h:hopen `:localhost:8888
q)h"1+1"
2
q)h"!5"
0 1 2 3 4
q)h"avg([1 2 3 4])"
2.5
q)h(`avg;1 2 3 4)
2.5
q)h(`add;3;4)
7
q)h(`hello;"q")
"hello, q"
q)h`total
100
q)h"data@<data"
1 2 3

    A string sent to a KlongPy server is Klong, not q. Klong error text is returned as the q error, with the wire name first:

    q)@[h;"nosuch(1)";{"caught: ",x}]
"caught: name: undefined function: nosuch"
q)@[h;"1+";{"caught: ",x}]
"caught: parse: missing right operand for +"
q)@[h;(`nosuch;1);{"caught: ",x}]
"caught: name: symbol not found: nosuch"

    At the default strict level, text that is not Klong can come back as a value instead of an error. h"til 5" is the name til followed by a 5 that the server drops, so the answer is the symbol `til and the server prints a warning. Start the server at strict level 1 or 2 (kgpy --strict=2 -s 8888) and the same request is answered with a parse error, as it is for any program that is not valid Klong. See strict mode.

    Variables can be set with a symbol call, and asynchronous messages (neg[h]) are accepted and run in order:

    q)neg[h]"hits::hits+1"
q)neg[h]"hits::hits+1"
q)h"hits"
2
q)h(`set;`bar;7)
q)h`bar
7

    The server had hits::0 defined. A one-character string is a character atom in q, so h"T" sends the character T and not a string of length 1; the server answers with that character. Write h"T " or h enlist"T" to send the name. If T is a klongpy.db table on the server, the answer is a table (type 98):

    q)type h enlist"T"
98h
q)cols h"T "
`sym`px
q)(h"T ")`px
1.5 2.5 3.5

    Hooks and the client's view of the connection are covered below. An open connection from a q client can be given a user name and password with .srv.auth; see Credentials.

    A function sent to q is its Klong source text, parsed by q. It runs only if that text is also valid q.

    Between two KlongPy interpreters¶

    The same calls work between two KlongPy interpreters; see the example in IPC Capabilities.

    Hooks¶

    q's .z.po and .z.pc run when a client opens and closes a connection, and .z.pw checks credentials. The Klong names are .srv.o, .srv.c and .srv.auth. .srv.e is called for an error that nobody is waiting for. There is no equivalent of q's .z.pg and .z.ps: a request is always evaluated as Klong source or as a call by name. The arguments and examples are in Server Callbacks and Credentials.

    .timer replaces .z.ts, as shown above. A call that gets no answer in 30 seconds fails with a timed out error; .clit(h;seconds) changes the limit.

    What is missing¶

    Compared with a q process:

    • No q-sql (select, update, exec, delete) and no by clause; use SQL strings over klongpy.db tables.
    • No typed nulls, no boolean, byte, short, int, real or temporal types. Temporal values from q arrive as plain numbers and 0N is not null.
    • A Klong table's key drives .insert upserts and maps to a keyed table over q IPC. Klong uses DuckDB SQL for table queries. q-sql attributes, enumerations, and q's splayed or partitioned file layout are outside the Klong table API.
    • No .z.pg, .z.ps, .z.pi or other message handlers; see Hooks above.
    • No true asynchronous send from Klong (q's neg[h]). .async(f;cb) sends a request and calls cb with the answer when it arrives; a KlongPy server does accept asynchronous messages from q clients.
    • Nested callbacks through a q process are not supported.
    • A function is sent as its source text. A projection arrives opaque and cannot be called by the receiver.
