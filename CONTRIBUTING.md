# Contributing

This file says how to propose a change. To build KlongPy, run the tests and change the code, read [docs/contributing.md](docs/contributing.md).

## Start with a discussion

New ideas, bug reports and questions start as a GitHub Discussion. Pick the category that fits: ideas and proposals, bug reports (with a reproducible case), questions, or experiments (benchmarks and alternative approaches).

Issues are not open for direct submission. A maintainer promotes a discussion to an issue when the problem is defined and the direction is agreed.

## Pull requests

A pull request without a prior issue is welcome when the change is small and its intent is clear from the description: a documentation fix, a bug fix, a small refactor. For anything larger, open a discussion first.

* Keep the change focused and match the existing style.
* Add a test, or a documentation example (see [docs/contributing.md](docs/contributing.md)).
* Do not mix in unrelated refactors.

## Conduct

Be respectful, assume good intent and criticise ideas, not people.
